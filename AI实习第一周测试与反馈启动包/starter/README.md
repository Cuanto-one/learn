# 第一周启动包：为知识图谱建立可信数据与证据

这是为承担知识图谱设计研发的 AI 专业研一学生准备的学习基线包，服务于“知识图谱 + RAG + 评测 + 工程”主线和 AI 实习准备。全部输入是程序生成或人工编写的虚构材料，不能用于诊断真实设备，也不能证明项目算法已有效。

这里的 `status.jsonl` 与 `lte.jsonl` 是为练习发明的 JSONL 格式，不是 `status.dat`、`record.dat` 或 `em350.dat` 的真实协议实现。没有真实业务报文输入；200 ms 仅用于时间网格练习。主从关系和异常状态也是合成设定，不构成真实故障标签。

## 从这里开始

1. 保留本包原样，在包外或新建的 `submission/` 文件夹写自己的答案。
2. 阅读本文和 `baseline_test.md`，先记录 Python、SQL、Git 的当前水平；关闭 AI 和既有答案。
3. 计时 120 分钟完成基线测试。到点停止，保留部分成果、报错及未完成项。**不要求做完整系统，未完成本身就是分流信息。**
4. 按检查清单评分；有评测者则请其核验。自评必须标记为“自测”。评分后再使用 AI 讲解、修复与复测。
5. 用 `weekly_review_template.md` 保存基线及后续反馈；能够写进简历的测量结果写入 `metric_card_template.md`。

全套可用 Python 标准库完成；常用模块包括 `json`、`datetime`、`pathlib`、`sqlite3`、`hashlib`。允许使用自己已经安装的 pandas，但不需要为测试安装依赖。SQL 小题可独立使用内存 SQLite，不依赖解析题是否完成。

## 业务阅读卡

本项目使用 DTE-L 汇集车载状态与业务信息。OCE 关联控制业务，CIR 关联时间、公里标、速度等信息，LTE 模块提供网络接入与信号状态。主控与从控机车需要结合对应网别的数据进行分析；不能因为时间接近就把不同机车的记录混在一起。

诊断流程会分别输出状态变化趋势、异常发生时段、候选故障类别、候选原因及检查建议。维修确认、日志证据和专家复核是不同来源的证据。只观察到信号下降，不能直接证明天馈故障；尚未确认的原因需要保留待复核状态。

项目材料提出不同采样周期及统一时间尺度。此题只用设备状态约 1 s、LTE 状态约 2 s 和 200 ms 分析网格进行缩小练习。真实协议、字段含义、设备时钟与采样边界仍须向项目确认；本题约定不能直接取代真实需求。

## 字段定义

JSONL 使用 UTF-8；行号从 1 开始，包含坏行。输入不能原地修改。缺失、乱序、重复与格式错误都是题目内容。

| 字段 | 类型与含义 |
|---|---|
| `vehicle_id` | 非空字符串；`SYN-` 开头的虚构机车标识 |
| `section` | 字符串 `A` 或 `B`，节位 |
| `network` | 字符串 `A` 或 `B`，网别；与节位是两个维度 |
| `role` | 字符串 `main` 或 `slave`，本题时间范围内固定 |
| `source` | `status` 或 `lte`，且必须与文件名对应 |
| `sequence` | 非负整数；不同设备允许相同序号 |
| `event_time` | 带时区的 ISO 8601 字符串，采集事件时间；可能用 `+08:00` 或 `Z` 表示 |
| `ingest_time` | 带时区的 ISO 8601 字符串，接收时间；延迟与乱序均可能存在 |
| `link_state` | 仅 `status`；`connected` / `disconnected` / `null` |
| `uptime_s` | 仅 `status`；非负整数或 `null`，模拟运行时长 |
| `attached` | 仅 `lte`；布尔值或 `null`，模拟入网状态 |
| `rsrp_dbm` | 仅 `lte`；数值或 `null`，模拟 RSRP；不能据此直接判根因 |
| `sinr_db` | 仅 `lte`；数值或 `null`，模拟 SINR |

所有所属类型的字段键都应存在。共同字段不得为空；业务值 `null` 是允许的缺失值，**记录保留，缺失另记**。共同字段缺失、时间无法解析或无时区、类型/枚举不符、来源与文件不符都属于非法记录。字段缺失与字段值为 `null` 不混为一谈。Python 的布尔值不视为合格的整数序号。

## 去重与追踪约定

1. 按 `dataset_info.json` 中的顺序读取文件，在文件内按物理行号读取。
2. 先解析和校验；坏 JSON 与非法记录进入拒绝记录清单，保留文件名、行号、原文和原因。
3. 把两个时间都转换为带时区的统一时间值（建议 UTC），保留原始时间字符串。不能用字符串排序比较不同偏移格式的时间。
4. 逻辑重复键为 `(vehicle_id, section, network, source, sequence, event_time_UTC)`。等价的 `+08:00` 与 `Z` 时间应视为同一时刻。
5. 同一键**保留读取顺序中的第一条合法记录**。后来的完全重复与数值冲突都记入重复清单，指出保留行与丢弃行；冲突另设标记。后到记录不自动覆盖先到记录。
6. 业务分析分组为 `(vehicle_id, section, network)`；各来源先在本组内处理，再按本组关联。不得按序号或时间单独跨设备关联。

质量报告至少能对账：物理行数 = 坏 JSON 行数 + 其他非法行数 + 合法重复行数 + 去重后保留行数。业务字段缺失记录仍包含在保留行中，不能再重复加到总数等式里。

## 时间网格约定

使用信息文件给出的 `[window_start, window_end_exclusive)`，步长 200 ms。按每个分组分别生成，不能把接收时间当采集时间。

- 对网格时刻 `t`，只能使用本组、本来源中 `event_time <= t` 的最近一条合法去重记录。相同事件时间存在不同合法序号时取最大序号；序号也相同则已经按重复规则处理。
- 状态记录的允许年龄为 1,000 ms，LTE 记录为 2,000 ms。**等于周期仍有效，大于周期才过期**。
- 没有过去记录时，该来源缺失。超过周期后保留最近采样时间和年龄，但将用于分析的业务值置为 `null`，标记过期。
- 最近记录的业务值本来为 `null` 时保留缺失，不能退回更旧的非空值覆盖它。字段缺失与来源过期要能区分。
- 输出至少包含分组键、网格时间、两类来源的最近采样时间、年龄、过期状态和业务值；格式可为 JSONL 或 JSON。

## 独立测试与新变体

独立测试时不使用 AI、搜索到的解题代码、生成器源码或上次完整答案；允许查官方语法文档，并记录查阅内容。真实工作中可以用 AI；此处单独测量自己可以承担什么。

第一次数据用于基线；评分后可以反复练习。未来由评测者选择新种子、生成新目录，只在测试开始时交付新 `inputs/` 与题面。例如在 PowerShell 中：

```powershell
python .\generate_variant.py --out .\future_variant_01 --seed 2045
```

若 `python` 不在 PATH，改为实际 Python 可执行文件。生成器拒绝覆盖已有目录。此工具不会评分，也不能保证题目对本人仍然陌生；若提前看过新输入、源码与参数，应记录为练习并换题。仅改变种子不能检验完全不同的工程需求，后续复测还应由评测者增加一项新约束。

合成数据检验实现行为，真实数据检验业务效果。通过本包不能据此声称已实现真实故障准确率、现场诊断耗时或原因未明件数降低。
